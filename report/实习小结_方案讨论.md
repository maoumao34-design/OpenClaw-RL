#### 引文选择的三处考量（勿走回头路）

1. **①② 必须同源** —— 曾拟从 SEA-Eval 取①的定义、从综述取②，被指出"什么是自进化怎么会从这篇来"。实际上**①② 是同一篇综述摘要里相邻的两句话**，一个出处覆盖两条更连贯。

> **第一个问题是它到底指什么。** 读下来我的理解是：关键在于部署之后模型还能不能变强——把交互中产生的经验，持续转化成自身的能力。这跟传统的"训练完上线就固定"是两回事。

>

#### 定稿过程中被否决的写法（勿走回头路）

| 曾经写法 | 为何否决 |
|---|---|
| ①「跨任务持续进化，而非单次任务表现好」| 讲的是**怎么衡量**不是**是什么**；且树了假对立（自进化不排斥单次任务做得好）；漏掉"经验转化为能力"这一核心机制。另外 ② 开头的"经验"会变成凭空冒出 |
| ②「有哪些实现路径」| 五个层面**不是互斥路线**，一个系统可同时用多层（MetaClaw 就用了两层）。"路径"暗示选其一，是误读；综述里它们是**经验的更新对象** |
| ③「工业界怎么做」| **MetaClaw 只是一次实验性尝试，不是工业化落地**（用户纠正）。综述明确说部署后训练仍处很早期阶段，用"工业界"会把领域成熟度说高 |
| ③「多数集中在技能与记忆层，触及模型权重的少」| **查证后综述里没有这个分布性结论**，属于编造，已替换为综述实际支持的内容 |
| ③「部署后训练仍处早期，公开证据稀少」| **这是"综述评审"的口吻——在给领域打分，不是在讲自己的工作**；且情绪往下走，听众会接一句"那你做这个有什么用"。改为「难点在哪」，保留综述最有价值的判断（瓶颈是系统工程不是算法），去掉成熟度评价。<br>→「还在探索期、没有完备路线」这个判断**保留在第8页收获①**：放在那里是**用户自己的判断**（做过才有资格说），放在第4页则成了**给领域打分**（越位）。同一事实，位置对了才成立。<br>→「公开证据稀少」这个事实不丢，放口述里正向表述："真正做成的公开案例还不多，所以更值得投入" |
| ④「不等空闲窗口」| ③ 改版后不再提"空闲窗口"，此说法在页面上失去对照对象，改为"训练直接跑在真实对话流中"，正好接住 ③ 的系统工程判断 |

#### Q&A 备份：五个层面 vs 两分法的归属关系

用户列了五个层面，被追问的风险随之而来，须备好此答案：

| 综述五个层面 | 归属 | 依据 |
|---|---|---|
| 技能（可复用流程）| 外部载体，不改模型 | 存下来复用 |
| 记忆（持久状态）| 外部载体，不改模型 | 同上 |
| 环境（可执行边界）| 外部载体，不改模型 | 综述 5.4 节标题直说"可执行、可复用 ≠ 可学习" |
| **模型权重**（RL / 持续学习）| **参数化，真正改模型** | 该章标题即"把经验固化进模型参数" |

**Separate / Joint 的准确差别**（源自 [`paper_reproduction_scope.md`](../docs/paper_reproduction_scope.md)「Joint vs Separate 区别」节）：
- **Separate**：三个角色各训一个**独立模型**，必须按 Student → TA → Teacher 依次跑——后一个角色要用前一个角色产出的**真实作业文件**当起点
- **Joint**：三个角色**共享同一个模型**（且是从基础模型重新开始训的新模型，**不接续** Separate 的 checkpoint，只复用其文件产出），三角色同时启动、互不阻塞；启动前需错位预铺三份作业目录，因此**必须建立在 Separate 已跑完的产出之上**

**配套口述稿（约 2.5 分钟）：**

> 这一页是 OpenClaw-RL 的完整实现。右边这张图信息比较多，我按左边这五条来讲，正好对应图上从上到下五个区域。
>
> **先看角色。** 论文的个人助理场景设了三种用户人设——学生、助教、老师，由一个 Qwen3-32B 的 Simulator 按人设扮演，跟被训练的 Policy 对话，Policy 是 Qwen3-4B。这里有个关键点：对话不是发生在一个模拟环境里，而是真的跑在 OpenClaw 这个 Agent 运行时中，工具调用和对话历史都由它维护——这一点最后我还会再提。三个角色之间是靠作业文件串起来的：学生做一份作业，助教在同一份文件上批改，老师再在批改结果上点评，后一个角色的输入是前一个角色真实产出的东西。
>
> **第二是训练顺序。** Separate 是三个角色各训一个模型，而且必须按顺序来——因为助教要批改的是学生真正做出来的作业，老师要点评的又是助教真正批改过的。Joint 则是三个角色共享同一个模型同时训练，代价是启动前得先把三份作业目录铺好，所以它反而必须建立在 Separate 已经跑完的产出之上。本次复现完成的是 Separate 这一条。
>
> **第三是一次回复的两条去向**，这是整套设计里我觉得最巧妙的地方。Policy 生成一次回复之后，它同时走两条路：一条是对话循环，回复照常送回给用户，对话不会因为训练而中断；另一条是训练循环，同一次回复被送去评估。这两条路是独立的——用户看到的回复，和用来训练的采样，互不干扰。
>
> **第四是信号从哪来。** 图上画了两个判官，但其实是同一个 PRM 模型、同一张卡、同一份权重，只是提示词不同。Eval 判官回答"这次回复有没有达成用户意图"，多次投票后给出 +1、-1 或 0，这个分数直接当奖励进 GRPO。Hint 判官回答"有没有可以吸取的教训"，给出改进建议，去重后留最多 K 条，再跟一份冻结的参考模型做 top-k 概率对比，得到 OPD 的损失。**一个回答"好不好"，一个回答"该怎么改"。**
>
> **第五是更新。** 两个损失加权合并成一个，只做一次反向传播，由 Megatron 更新 Policy 权重，新权重再同步回线上的 Policy 服务。
>
> **最后强调一点。** 整套训练是跟对话异步并行的——用户那边回应照常送出，权重在背后在线更新，全程不需要停机重训。而且训练用的就是推理时用的那个真实运行时，不是另外搭一套简化的模拟环境。这听起来像工程细节，但它决定了训练出来的行为能不能真的迁移到线上：如果训练时的环境和上线后的环境不一样，那就又回到了训练和部署脱节的老问题。

#### 背景参考（不是幻灯片内容，帮助口述时讲准）

**1. 目标（关键，容易讲偏）**
**不是复现 MetaClaw 论文的结果**，而是把已在 Personal Agent 场景复现并校准好的 Hybrid RL 方法，原样搬到 MetaClaw-Bench 这个全新场景，**验证方法的普适性**。

**2. 哪些不变、哪些换掉（这页的灵魂）**

| 环节 | Personal Agent（已复现）| MetaClaw 迁移 |
|---|---|---|
| 训练后端 | Megatron + slime | **不变** |
| RL 算法 | GRPO + OPD topk-select | **不变** |
| 奖励来源 | PRM 主观判断 | 换成 Bench 自带的**确定性 checker**（file_check 看 exit code；multi_choice 精确匹配打分）|
| OPD hint | PRM 投票生成 | 换成 checker **实际执行输出**（不能用静态 `feedback.incorrect`）|
| 环境 | Simulator 扮三角色对话，GSM8K | 模型当 CLI agent，MetaClaw-Bench 30 天任务流 |

- **前两行"不变"是重点** —— 迁移的是方法本身；后三行换掉的都是场景相关部分
- **MetaClaw 场景不需要外部 Simulator**，相比 Personal Agent 反而是简化
- **不迁移**：技能库（gradient-free 快通路）、OMLS 空闲窗口调度、skill versioning

**3. 成功标准（写进 PPT 是加分项）**
- 主：相对**同一模型的无训练基线**有明显提升
- 过程：逐日准确率曲线出现类似论文 Figure 2 的"信号攒够后提升"的拐点
- **明确不追求**达到论文中 GPT-5.2（41.1%）/ Kimi-K2.5 Full（40.6%）的绝对分数——模型量级差距过大，不构成公平对照。**这条说明用户知道什么样的对比才有意义**

指标口径：**Acc.** = 全部题目平均分；**Compl.** = 仅 file_check 子集通过率。打分方式跟论文 Table 1（Full 档）一致：**边训练边实时算分、同一趟聚合**，论文自己也没有 held-out 测试集。
