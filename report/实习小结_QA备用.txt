二、第 4 页 · 自进化调研
══════════════════════════════════════

【问】五个更新层面怎么理解？能不能简化成两类？
【答】可以概括成「经验存哪儿」：技能、记忆、环境三层是外部载体，不改模型权重；模型权重层才是真正改参数；元控制是上层调度，决定更新哪一层，不属于前两类。比例大致是 3（外部）: 1（权重）: 1（元控制）。

【问】元控制算参数化还是非参数化？
【答】都不属于。前面几层回答「经验存到哪儿」，元控制回答「谁来决定去更新哪一层」，是调度问题，综述里单独成章。

【问】为什么选 OpenClaw-RL？是不是随便找一篇论文？
【答】不是。一篇自进化综述明确点名 OpenClaw-RL，把它归在「把部署后在线学习说得最明确」的一类系统，和 MetaClaw 并列。我复现的是这篇综述点名的代表作之一。

【问】迁移 MetaClaw 进展怎么样了？（若在第 4 页被追问）
【答】那是第 7 页的内容，Personal Agent 复现校准完成后才做泛化验证；第 4 页只讲调研坐标，不展开迁移进度。

【问】环境故障和模型失败怎么区分？
【答】这是本次实验踩坑最多的地方。超时、503、生成失败若误判成「模型做错了」，等于往训练里灌毒信号。需要结合日志看是基础设施问题还是 Policy 输出本身有问题。


══════════════════════════════════════
三、第 5 页 · OpenClaw-RL 实现方法
══════════════════════════════════════

【问】Joint 做了吗？为什么只做 Separate？
【答】本次复现完成的是 Separate：三个角色各训一个独立模型，必须按 Student → TA → Teacher 依次进行，后一个角色要用前一个角色真实产出的作业文件。

Joint 是三个角色共享同一个模型、同时训练；启动前要预铺三份作业目录，必须建立在 Separate 已跑完的产出之上。Joint 是从头训的新模型，不接续 Separate 的 checkpoint。

【问】图里两个 Teacher 是不是搞错了？
【答】不是同一个概念。Student/TA/Teacher 里的 Teacher 是用户人设（老师角色）；OPD 里的 PRM Teacher 是 Policy 权重的冻结参考副本，用于蒸馏对比。只是重名。

【问】为什么一定要在 OpenClaw 里训练，不能简化模拟？
【答】训练必须跑在推理时用的真实运行时里，否则训练和上线环境不一致，部署后学习就失去意义。这次是真在 OpenClaw 里训，不是搭简化环境。

【问】Eval 和 Hint 是两个模型吗？
【答】不是。同一个 PRM 模型、同一份权重、同一张卡，只是提示词不同：Eval 答「好不好」进 GRPO；Hint 答「该怎么改」进 OPD。


══════════════════════════════════════
四、第 6 页 · 复现实验结果
══════════════════════════════════════

【问】Table 3 这个指标到底是什么？
【答】不是准确率，是「达到优化效果所需的最少 session 数」，越小越好。规则化判定：连续 3 个 session，模型对用户第一句话的回复都满足偏好，就算收敛。

【问】19.2 和 20 能算复现成功吗？
【答】基本重合。但要说明口径：论文 19.2 是五次独立试验的均值，我这是单次运行，严格说不是同一统计口径。

【问】为什么 Simulator 跟论文不一样？第 5 页还写 Qwen3-32B？
【答】第 5 页描述的是论文方法配置；第 6 页是本次实际配置。论文规定 Simulator = Qwen3-32B，我换成了 DeepSeek-V4-Flash——原 Simulator 理解能力不够，常把本该通过的回复判成不合格，实验推进不下去；换更强的之后才稳定。这说明瓶颈可能在评判方，而非被训练的 Policy。

【问】为什么只跑了 34 个 session，不是 72 题？
【答】日志对应 Separate-Student 单次运行，实际完成 34 个 session；展示到收敛为止，收敛之后的问题与论文实验口径无关。

【问】「15 次有效回复」分母为什么不是 17？
【答】第 32、34 个 session 实际是「无回复 / 生成失败」。因不含 bold 与编号列表，会被格式规则误判为达标，已从统计中剔除。

【问】学生抱怨 equation look，算不算没收敛？
【答】那是 LaTeX 排版（日志里 \text{}、\frac{} 等），论文规则不检查 LaTeX，只查 bold / 编号列表 / \boxed{}。Simulator 的实际偏好可能比论文规则更宽。

【问】第 20 个 session 只有结论没有过程，算不算作弊？
【答】这版指标只看格式是否满足偏好，该 session 按规则算达标。内容完整度是下一步要解决的问题。

【问】收敛后为什么不再展示？
【答】收敛之后的问题多属 Simulator 缺陷，与论文 Table 3 实验无关，故不展示。


══════════════════════════════════════
五、第 7 页 · 方法泛化方案
══════════════════════════════════════

【问】这是在复现 MetaClaw 论文吗？
【答】不是。目标是把 Personal Agent 场景已复现校准的 Hybrid RL 方法，搬到 MetaClaw-Bench 新场景，验证方法普适性。不迁移 MetaClaw 技能库、OMLS 调度等。

【问】37.3% 能和 Kimi-K2.5 的 40.6% 直接比吗？
【答】不能严格同条件对比。这是数量级参照：4B 模型、只用 RL、不含技能库，落到 Kimi + 完整 MetaClaw 管线附近。模型量级、评测环境都不同，也不追求达到 GPT-5.2 / Kimi Full 的绝对分数。

【问】打分方式跟论文一致吗？要不要用官方 bench 单独重评？
【答】一致。论文 Table 1 Full 档就是同一趟 30 天边训边打分、live 聚合，前面天数用未训好权重、后面用训过权重混在一起平均。论文自己也没有「训完固定权重再单独重评」。本次 37.3%/13.9% 跟论文方法学一致，不是需要修的偏差。官方 bench 单独复核只能是额外校验，不是纠偏。

【问】提升会不会只是「混合权重状态」造成的假象？
【答】全程 live 聚合本身就是论文认可的主指标。若追问，可补充诊断：Train day1-6（滚动权重）Acc.=61.4% / Compl.=45.0%；Frozen day7-30（固定 ckpt）Acc.=31.9% / Compl.=7.1%。冻结段单独看仍高出基线同范围约 16pt。

【问】基线 17.8% 怎么来的？跟早期 5.7% / 8.1% 什么关系？
【答】Acc.=17.8% / Compl.=0.0%（seed 465485731）是 --agent 修复后重新定版的基线，与本次训练同一批修复，对比干净。早期 5.7%、8.1% 等旧基线已作废，不要再引用。

【问】迁移时到底换了什么、没换什么？
【答】
不变：Megatron + slime 训练后端；GRPO + OPD topk-select 算法。
换掉：奖励来源（PRM 主观 → Bench 确定性 checker）；OPD hint 来源；环境（三角色对话 → CLI agent 30 天任务流）。
新增：round 内多轮 tool-call 的中间轮次步骤判官（LLM 打分，RL-only，不聚合进 round 总奖励，不走 OPD）。

【问】「不再需要 LLM 判官」和「中间轮次用步骤判官」矛盾吗？
【答】不矛盾。限定在 round 最终轮次：Eval/OPD hint 改由 Bench 确定性反馈提供。中间轮次没有客观对错，另加步骤判官——两篇论文都没给现成答案，是自行定案。

【问】OPD hint 和模型看到的 [Previous Feedback] 是一回事吗？
【答】不是。OPD teacher hint 进蒸馏损失；agent 下一题看到的可见反馈是另一条路。K=6 实验时 OPD 已用 checker 真实 stdout（file_check）或错选项说明（multi_choice），但可见反馈里追加 stdout 是更后面的改动。

【问】训练为什么跑不满 30 天？
【答】目前主要问题是训练后期长思考空转。三处根因已定位并实现修复，下一步验证能否稳定训完整趟。K=6 冻结窗口是权宜之计（训不满 30 天时跑完剩余天数），不是长期方法学设计。

【问】K=6 实验包含最新修复吗？
【答】K=6 用的是 commit 0882f69，不含后来 day12-14 长思考空转的三处修复。冻结窗口 day6 后不再训练所以没崩，不代表那个问题已解决。

六、第 8 页 · 实习收获
══════════════════════════════════════

【问】Multica 和「掉了么」是一回事吗？
【答】不是。Multica 是自研多智能体协作平台（工具）；「掉了么」是联想暑期活动里小组从 0 到 1 做的可视化产品，碰巧建在 Multica 上。第 8 页讲平台体验，第 9 页讲团队活动。

【问】非参数化和参数化是替代关系吗？
【答】不是，是互补。OpenClaw-RL 改权重，慢、代价高、但能真正长能力；Multica 类平台靠记忆和技能沉淀，快、零停机，但模型本身不变。MetaClaw 自己就并行用了两层。

【问】多智能体协作有什么具体优势？（若追问收获②）
【答】保持概括即可，不必展开具体例子（已定稿）。可补一句：完整产品开发 + 向平台提改进意见，说明不是浅尝辄止。

【问】OpenClaw-RL 复现到什么程度？
【答】采用中性表述：「复现并验证了 OpenClaw-RL 的核心机制」——属于参数化一端，且把权重更新做进真实对话流。

八、第 10 页 · 职业规划
══════════════════════════════════════

【问】短期目标怎么还是做 OpenClaw 复现？
【答】职业规划讲未来，不讲这次实习已做的事。短期是从「复现」走向「独立」——能自己判断方向价值、设计实验路径，做出经得起推敲的结果。

【问】是不是只打算做自进化这一个方向？
【答】职业规划讲能力与角色进阶，不绑定单一研究方向；换技术方向这套规划照样成立。行动上会高频跟进自进化主线，但不等于排斥其他热点。

【问】长期目标是什么？
【答】提出有原创性的方法或理论，在所处方向上形成影响力，让工作成为别人的参照——一句话：从跟随前沿，到定义前沿。


══════════════════════════════════════
九、跨页 / 综合类（可能被深挖）
══════════════════════════════════════

【问】这次实习最大的技术贡献是什么？
【答】三件事串起来：Personal Agent 场景复现并校准 OpenClaw-RL；Separate-Student 收敛结果与论文基本重合；同一套 Hybrid RL 迁到 MetaClaw-Bench 有明显提升，说明方法不只适用于单一场景。

【问】遇到的最大困难是什么？
【答】不在 RL 算法本身，而在「经验 → 更新」链路：信号提取、区分环境故障与模型失败、在真实运行时里跑训练。Personal Agent 和 MetaClaw 迁移各有一套场景特有难题。

【问】如果重新做，会改什么？
【答】（按真实体会答，可提）更早锁定 Simulator/评判链路问题；迁移实验尽早统一基线口径；训练稳定性问题优先于额外评测协议。

【问】论文 v1 和 v2 有什么区别？你复现的是哪个？
【答】v2：三角色 Student/TA/Teacher、session 收敛数指标、topk_select 方法。本项目从一开始就是按 v2 复现。

【问】为什么不在答辩里讲梯度爆炸、版本考古那些工程细节？
【答】转正答辩时间有限，评委更关心判断和方法；这些细节 Q&A 里可以答，但不适合占主线。
