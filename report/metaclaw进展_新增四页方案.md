## 已定的原则

1. **按"同一对照、只改一个变量"分组**：9/18 之后做了三组对比实验，每组一页
2. **版式照第 5 页**：一张同窗对照表 + 几条要点
3. **窗口按每组实际切**：取组内各趟都跑到的天数，按实际起病日分段，不套统一窗口。具体切点等 CLI 逐日数据回来再定
4. **最后一页做总结**，不写原因分析和下一步
5. **不写专利相关内容**（仓库是公开的）
6. **没跑的题不计 0**（10-14 确认，规则见下）

### 计分与窗口规则

| 情况 | 处理 |
|---|---|
| 跑了，答错或 idle timeout | 计 0（真实结果）|
| 跑了，infra failure | 计 0，另列一列计数 |
| 根本没跑（训练停掉之后的天）| **不计 0，不进分母** |

- 每组窗口截止到**组内最早停下那趟的最后一个完整天**；没跑完的那一天也排除（只跑了前几轮，题目构成和其他趟不一样）
- 未跑完的趟**不引用 30 天总分**。work_log 里 H0 的 22.8%（79/346）把 day21 之后没跑的题按 0 计入，不能和真跑满 30 天的熵趟 16.5%（57/346）直接比
- 崩溃程度靠"首次成批复读""跑到""DROPPED"这几列表达，不靠把剩下的天折成 0
- **为什么改**：以前把没跑完当 0，前提是"没跑完 = 跑不完"。但这几趟停止原因不同（遮罩趟 driver 被信号终止，同策略趟 driver 中途死掉），一律算 0 会把外部原因记成模型失败。停止原因由 CLI 归类（训练崩溃 / 外部原因 / 不确定）
- **已汇报的第 5 页不受影响**：它的 day09–20 窗口在 H0 实际跑到的范围内（H0 停在 day21 第 6 轮）

| 组 | 各趟最后一个完整天 | 共同窗口上限 |
|---|---|---|
| 消融 | 混合 day20、纯 RL 约 day27、纯 OPD 待查 | ≤ day20 |
| 正则 | 混合 day20、KL day21、熵 day30 | day20 |
| 机制·遮罩 | 纯 OPD 待查、遮罩 day18 | ≤ day18 |
| 机制·同策略 | 混合 day20、同策略 day09 | day09 |

以上"最后一个完整天"按 work_log 记录的停止位置推算，以 CLI 结果为准。

## 第 6 页：消融实验 —— RL 和 OPD 各自的作用

| 实验 | Run ID | 设置 | 跑到 | 首次成批复读 | 崩法 | DROPPED |
|---|---|---|---|---|---|---|
| 零训练基线 | `20260907_112320` | — | 30 天 | 无 | 不崩 | 0 |
| 混合（对照）| `20260914_181842` | RL + OPD | day21 | day09 | 复读 thinking → idle timeout | 93 |
| 纯 OPD | `20260917_163256` | 去掉 RL | 待查 | day04 | 复读 thinking → idle timeout | 9 |
| 纯 RL | `20260917_180600` | 去掉 OPD | ~day28 | 不复读 thinking | day08 前兆，day13 起反复 write → transcript 撑爆 → Compaction 超时 | 16 |

**窗口（初步）**：day01–03（三趟都健康）/ day04–08（只有纯 OPD 崩了）/ day09–20（混合也崩了；纯 RL 在 day13 起崩，段内可再拆）。上限 day20 由混合趟决定，纯 OPD 若停得更早则随之提前。

**可写的要点**：
- 零训练基线 DROPPED 为 0：超长轮次完全是训练造成的，不是题集本身的性质
- 复读 thinking 只出现在开了 OPD 的训练里；纯 RL 的 thinking 反而变短（4k → 2.4k），崩法是反复写同一个文件（day18 一轮里 `write prod_config.py` ×499）
- 起病顺序：纯 OPD day04 < 混合 day09 < 纯 RL day13

**待补数据**：三趟的逐日 Acc / Compl；纯 OPD 跑到哪天。

## 第 8 页：机制验证实验 —— 两个假设各一个对照

| 假设 | 对照 | 实验 | Run ID | 结果 |
|---|---|---|---|---|
| H-e：OPD 压低了"停止思考"，模型越想越长 | 纯 OPD `20260917_163256` | 纯 OPD + 遮住 OPD 对停止和动作的作用 | `20260930_212143` | 仍是 day04 起病、day05 有 21/22 在复读，**一天没推迟 → 否定** |
| H-f：训练用了旧权重生成的样本 | 混合 `20260914_181842` | 混合 + 只用当前权重生成的样本 | `20261012_072251` | 到 day09 没有成批复读（对照 day09 为 29%）；但到 day09 只训了 8 步，对照起病在第 11 步 → **未定论** |

**窗口（初步）**：遮罩组 day01–03 / day04–18（遮罩趟停在 day19 第 2 轮，day19 不完整，排除）；同策略组只能看 day01–09（day10 不完整，排除），另标训练步数。

**可写的要点**：
- 遮罩有效：每步 OPD 仍作用的位置占比 0.828–0.975，7 步全在事先定的 [0.8, 1.0) 内
- 遮住停止决策后照样崩 → 问题出在 OPD 作用于 thinking 内容的部分
- 同策略过滤生效：样本新旧差（`train_rollout_logprob_abs_diff`）多数步回到 step 0 底线附近；此前各趟多为底线的 1.4–2.7 倍
- 同策略趟 day08 有一个 95 turn 的超长轮次被丢弃（不是复读 thinking，在重复做什么待查）；driver 在 day10 中途死掉

**待补数据**：遮罩趟逐日 Acc / Compl 和 DROPPED；混合趟 day09 及以后逐日数。
